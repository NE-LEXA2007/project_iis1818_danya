# КредитНавигатор

## Часть 1. Техническое задание

### 1. Название системы и автор

(номер и описание взяты из приложенного материала «Промпт-ИИС-для-друзей.md»;
сам банк тем в приложенных PDF отсутствует).

### 2. Предметная область

Публичные условия одного банка — Райффайзенбанка — для потребительского кредита наличными. Система находит условия ставок, платежей, просрочек и досрочного
погашения. Такая область требует ссылок на документы и различения продуктов:
условие по карте нельзя выдавать за условие кредита наличными.

Корпус: два PDF, 26 страниц. Загружены 26.10.2026 с официального сайта:

1. **Общие условия обслуживания счетов, вкладов и потребительских кредитов граждан
   АО «Райффайзенбанк»**, действуют с 19.10.2026.
   https://www.raiffeisen.ru/common/img/uploaded/files/retail/creditcard/ou_rus.pdf
   Файл `raiffeisen_cash_general.pdf` — 21 страница: исходные страницы 1–14 и 70–76
   (титул, термины, раздел 8). Хотя путь URL содержит creditcard, название и раздел 8
   относятся также к потребительскому кредиту. Ссылки в ответах указывают страницу
   **извлечённого PDF**: 1–14 = оригинал 1–14, 15–21 = оригинал 70–76.
2. **Преддоговорное информирование о предоставлении потребительского кредита**.
   https://www.raiffeisen.ru/static/common/DLPI/Preddogovornoye_sept.pdf
   Файл `raiffeisen_cash_precontract.pdf`, 5 страниц без изменений.

Проверка `python scripts/check_corpus.py`: pypdf извлёк непустой текст из всех
21/21 и 5/5 страниц, SHA-256 совпали; первые 300 символов каждого файла выведены.
Ссылки, SHA-256 оригиналов и извлечений, отображение страниц — в `data/sources.json`.
Документы разных редакций: при расхождении условий нельзя усреднять ставки или
переносить пример из преддоговорной информации в индивидуальный договор.
Изначально рассматривался Т-Банк, но прокси не доверяет его TLS-сертификату;
выбран доступный официальный источник без отключения проверки сертификатов.

### 3. Целевая аудитория

Сотрудник первой линии банка, который объясняет клиенту типовые условия, но не
определяет персональную ставку и не принимает решение об одобрении.
Сейчас он открывает PDF условий нужного продукта и вручную ищет пункт по
терминам документа. Клиент часто формулирует вопрос бытовыми словами;
ассистент должен помочь найти соответствующий пункт и сохранить его оговорки.

### 4. User Stories

1. Как оператор по кредитам наличными, я хочу найти правило о процентах со ссылкой,
   чтобы объяснить клиенту формулировку условий, а не назвать придуманную ставку.
2. Как сотрудник кредитной поддержки, я хочу уточнение продукта при неоднозначном вопросе,
   чтобы не применить правила другого договора.
3. Как специалист по погашению, я хочу найти порядок полного и частичного досрочного
   погашения, чтобы перечислить только предусмотренные документом действия.
4. Как сотрудник по просроченной задолженности, я хочу увидеть основание и размер
   санкции из документа, чтобы проверить ответ по первоисточнику.
5. Как оператор, я хочу продолжать диалог в отдельной сессии,
   чтобы обсуждать предыдущий ответ без доступа к чужой истории.

### 5. Архитектурные рамки

**Входит в MVP:**

- Поиск ставок и условий в документах выбранного продукта со ссылками (история 1).
- Уточнение продукта перед применением разных условий (история 2).
- Отдельный маршрут для досрочного погашения (история 3).
- Отдельный маршрут сверки просрочек и санкций (история 4).
- SQLite-память, последние 10 сообщений, изоляция и сброс сессий (история 5).
- ChromaDB, мультиязычные эмбеддинги, поиск через MCP, GigaChat или Ollama.

**Не входит в MVP:**

- Индивидуальный расчёт ставки, решение об одобрении и кредитный скоринг.
- Кредитные карты, ипотека, автокредиты, другие банки и сравнение предложений.
- Юридическая консультация и толкование законов, не включённых в корпус.
- Обработка паспортов, карт и личных кредитных договоров.
- Обновление тарифов в реальном времени и выполнение банковских операций.
- Практики 6–8: LLM-судья, полноценная защита от инъекций и расчёт TCO.
  Соответствующие модули исходного шаблона пока содержат учебные заглушки.

### 6. Метрики успешности MVP

| Слот | Метрика по кредитным условиям | Цель | Инструмент | Первый замер |
| --- | --- | --- | --- | --- |
| Поиск | Документ с условием входит в первые 5 фрагментов, 4 вопроса с источниками | hit-rate@5 ≥ 75% | `ingest.evaluate_retrieval()` | П2 |
| Ответ | Утверждения о ставках, сроках и санкциях подтверждены контекстом, 10 вопросов | Faithfulness ≥ 0,8 | `test_suite.judge()` | П6 |
| Расход | Сумма входных и выходных токенов за фиксированный диалог о платеже, просрочке и досрочном погашении | ≤ 12 000 токенов | `finops.measure_dialog()` | П8 |

Это цели, а не результаты. В П2 пятый вопрос вне базы не входит в знаменатель;
цена деления 25%. Для cross_section дополнительно проверяются оба источника:
шаблонный hit-rate проверяет только попадание хотя бы одного из них.
Результаты подбора нарезки и фиксация цели приведены в `reports/practice-02.md`.

### 7. Работа с персональными данными

1. По проектному замыслу персональные данные не собираются, в корпусе только
   публичные условия продукта (в титуле есть публичное ФИО подписанта Монин С.А.).
   Пользовательские ПДн **могут попасть во внешний API**, если
   оператор сам введёт их в вопрос: туда отправляются вопрос, история и фрагменты.
2. Возможные данные — ФИО, номер договора, сумма личного долга. Автоматического
   обезличивания в П1–П5 нет. До использования GigaChat оператор должен удалить
   такие сведения; для чувствительных запросов предусмотрена локальная Ollama.
   Локальная модель не отменяет необходимость защищать SQLite-файл истории.

Идентификатор веб-сессии — UUID, не связанный с личностью. Не вводите реальные
клиентские данные. История хранится локально; кнопка очистки удаляет её.
TLS-проверка GigaChat включена. Практика 7 ещё не выполнена: защиту от инъекций
и нормативное соответствие 152-ФЗ эта версия не гарантирует.

## Часть 2. Установка и запуск (Linux, WSL, macOS)

Python 3.11. Запускайте из корня репозитория:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install 'torch==2.5.1+cpu' --index-url https://download.pytorch.org/whl/cpu  # Linux CPU
python -m pip install -r requirements.txt
python -m pip check
cp .env.example .env  # только если .env ещё не существует
```

На macOS вместо строки с CPU-репозиторием: `python -m pip install torch==2.5.1`.
Для сдачи выберите `LLM_BACKEND=ollama` и запустите установленную Ollama:

```bash
ollama serve
# в другом терминале
ollama pull qwen2.5:3b
```

Либо `LLM_BACKEND=gigachat` и задайте `GIGACHAT_CREDENTIALS` локально в `.env`.
Не отправляйте ключ в чат или Git. Проверку TLS не отключайте; при необходимости
установите доверенный сертификат провайдера.

### Документы и индекс

```bash
python scripts/download_corpus.py  # проверяет SHA-256, не перезаписывает изменённые файлы
python scripts/check_corpus.py
python ingest.py
python ingest.py --eval
```

`gold_dataset.json` содержит 5 вопросов: два прямых, один по двум файлам,
один бытовыми словами и один вне области. Эталоны — цитаты из извлечённого текста.
Если официальный URL сменит редакцию, загрузчик остановится: нужны новые
проверенные источники и пересмотр эталонов, а не отключение контроля суммы.

Для подбора нарезки используйте `python scripts/benchmark_retrieval.py`.
Скрипт меняет один параметр за раз, не редактирует config.py, сохраняет JSON-отчёт
и в конце восстанавливает индекс с параметрами из config.py.

### Проверки

```bash
python -m unittest discover -s tests -v
python scripts/integration_check.py  # настоящие E5/Chroma/MCP, отдельные синтетические данные
LLM_BACKEND=fake python scripts/smoke.py  # отладка конвейера, не сдача П4
LLM_BACKEND=ollama python scripts/smoke.py  # нужен корпус, индекс и настоящая модель
streamlit run app.py --server.headless true
```

`fake` не заменяет языковую модель. Unit-тесты используют явно синтетические
фрагменты и HTTP-моки: они проверяют код, а не качество банковских ответов.
`test_suite.py`, `guardrails.py` и `finops.py` — задания последующих практик.

## Часть 3. Сдача

История содержит отдельные этапы: шаблон, ТЗ, обработка, оркестратор, LLM, память.
Отчёты в `reports/` явно отделяют сделанное от непроверенного.

```bash
mkdir -p ../bundles
git bundle create ../bundles/Фамилия-П5.bundle --all
git bundle verify ../bundles/Фамилия-П5.bundle
```

Один актуальный bundle можно копировать под нужными именами, если это разрешено
преподавателем; его содержимое и история при этом остаются одинаковыми.
Переименование не означает, что непроверенные этапы успешно сданы.
В СДО загрузите файл вручную: доступа к вашей СДО в этой среде нет.
