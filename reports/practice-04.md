# Практика 4: клиенты и промпты

Реализованы GigaChat через официальный SDK и Ollama через /api/chat.
Общий интерфейс generate() сохранён. В GigaChat температура не ниже 0,01,
count_tokens() использует tokens_count() с локальной оценкой при ошибке.
Сетевые ошибки возвращают понятное сообщение, секреты и трассировки не печатаются.
TLS-проверка включена; доверие к сертификатам не отключалось.

Системные промпты разделены по ролям, примеры взяты из реального корпуса:
возраст заёмщика, пункт 8.7.1 о досрочном возврате и 8.9.2 о неустойке.
Порядок сообщений: system → история user/assistant → контекст и текущий вопрос.
Вставка system из истории отбрасывается.

Блок <think> удаляется: промежуточное рассуждение модели не является
проверенным ответом по кредитным условиям. Для локальной проверки выбран
Qwen2.5 3B в Ollama; DeepSeek-R1 1.5B установлен, но на коротком русском вопросе
дал неудачный ответ «Сумма», поэтому как основной бэкенд не выбран.

Unit-тесты проверили payload обоих клиентов, безопасную обработку ошибки,
подсчёт токенов, порядок сообщений и удаление <think>.
GigaChat проверен с моками SDK: реального ключа в среде нет, запросы к API не делались.
Результат реального Ollama-диалога приведён в итоговом отчёте; моки не считаются
подтверждением качества LLM.

Ollama: контекст 8192 токена и максимум 512 выходных токенов. Без ограничения
первый общий вопрос порождал длинный ответ, а последующий диалог был медленным;
первый диагностический прогон остановлен и заменён ограниченным повтором.
Это настройка расхода и времени, а не доказательство качества ответа.
