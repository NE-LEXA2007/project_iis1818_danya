# Проверка проекта П1–П5

26.10.2026. Linux cloud, Python 3.11.17, CPU (квота 4 ядра).

## Подтверждено

- 13 unit-тестов завершились успешно (`unittest discover -s tests -v`).
  Проверены очистка, покрытие текста окнами, рубрики, автомат, запрет перехода,
  сборка промпта, клиенты с моками, изоляция/перезапуск SQLite и перенос контекста.
- Настоящие E5 + Chroma + MCP: поиск, фильтр category и чтение истории прошли
  в отдельном временном каталоге на явно синтетических данных.
- Официальные PDF: 26/26 страниц дают текст, контрольные суммы проверены.
  В отдельном пустом каталоге документы скачаны заново; PDF-извлечение воспроизвело
  сохранённый SHA-256 побайтно.
- Три замера retrieval и итоговый индекс: 261 фрагмент, hit-rate@5=4/4.
  Категории: early_repayment 31, penalties 18, rates 38, terms 75, general 99.
- Для сравнения документов source-фильтр MCP вернул оба файла:
  общие условия, стр. 18; преддоговорное информирование, стр. 3.
- Ollama 0.40.11 установлена из официального GitHub-релиза. SHA-256 архива
  проверен по опубликованному sha256sum.txt. Загрузка моделей также проверила SHA-256.
- Реальная Qwen2.5 3B ответила через OllamaClient на контрольный вопрос «два плюс два» числом 4.
- Три вызова Orchestrator.handle() на настоящем банковском индексе и Qwen2.5 3B
  завершились, содержали 21/67 и ссылки. После них в SQLite было шесть сообщений;
  smoke-тест очистил только свою сессию и закрыл MCP.
- Streamlit: HTTP health вернул ok; AppTest отрисовал заголовок, элементы сессии
  и поле чата без исключений. Это проверка рендера, а не browser E2E.
- pip/uv check: все 142 установленных пакета совместимы.
- contracts.py, mcp_client.py, mcp_server.py, vk_bot.py, fake_llm.py не менялись.
  .env, исходные PDF, индекс и SQLite исключены из Git.

## Реальный диалог

1. «Какой минимальный возраст указан в преддоговорном информировании о
   потребительском кредите?» → «...от 21 года на момент предоставления кредита
   и до 67 лет на момент окончания действия кредитного договора.
   [raiffeisen_cash_precontract.pdf, стр. 1]».
2. «А какой максимальный возраст на момент окончания договора?» →
   «...до 67 лет. [raiffeisen_cash_precontract.pdf, стр. 1]».
3. «Повтори возрастные ограничения из первого и второго ответов одним предложением.» →
   «Минимальный возраст для предоставления кредита указан как 21 год, а максимальный
   возраст на момент окончания действия кредитного договора — до 67 лет.
   [raiffeisen_cash_precontract.pdf, стр. 1] [raiffeisen_cash_general.pdf, стр. 1]».

Последняя ссылка на титульную страницу общих условий избыточна и не подтверждает
возраст. Наличие верной ссылки на преддоговорный файл не исправляет эту неточность.
Это ограничение качества модели, а не пройденная Faithfulness-оценка. Возраст есть
и в few-shot примере: сам этот диалог не является независимым доказательством
семантического использования памяти; передача истории подтверждена тестами и SQLite.

- Faithfulness, 10-вопросный набор и LLM-судья относятся к П6 и ещё не реализованы.
- Полная защита ввода и TCO относятся к П7/П8; соответствующие заглушки шаблона
  оставлены явно незавершёнными. Проект нельзя использовать с реальными клиентскими данными.
- Первоначальный диагностический диалог с широким вопросом был медленным;
  его остановили, добавили лимит ответа 512 токенов и повторили проверку полностью.
- Оценка hit-rate проверяет имя файла, не доказательство каждого утверждения.
- Группа автора уточнена 11.11.2026: БФБО-06-24, внесена в README.
- Доступа к СДО нет; файлы для сдачи загружаются пользователем.
- Публикация cloud-снимка выполняется пользователем; восстановление в новой задаче
  пока не проверялось.
